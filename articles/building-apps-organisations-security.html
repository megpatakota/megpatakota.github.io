Building Apps Inside Organisations: The Security Work Beyond the Demo

A practical guide to the decisions between a working app and a responsible rollout: permissions, data boundaries, AI actions, evidence and ownership.

In this article

An AI demo can draft a document. A shared app must keep each workspace’s files separate, control who can edit its drafts and approve what reaches a client.

The backdrop is an AI document workspace. Internal users create workspaces, invite colleagues and add source files. AI uses those files to write deliverables—draft documents for internal use or client sharing. Each workspace has its own files, members and permissions. The scenarios below are illustrative: each follows a different failure through prevention and testing.

Create workspace→Add source files→AI writes a draft→Review and share

Check workspace access before AI starts writing

Scenario: A colleague joins Workspace A, but an AI draft includes confidential files from Workspace B.

Signing in confirms identity. The server must separately check permission to create a workspace, upload files, read sources, edit a draft or share a deliverable. Client access to a finished document must not automatically grant access to its source files.4428

Restricted content appears

What to do
Check both user access and workspace membership before model access. A writing request must not pull files from another workspace.
How to test it
Try another workspace’s file and draft IDs. Test colleagues with different roles and a client who can only read the shared deliverable.

Removed access still works

What to do
Define how quickly removed access must take effect. Update search permissions and clear affected stored drafts.
How to test it
Remove a user’s access, then retry search, source links and saved deliverables.

A citation misleads

What to do
Keep source references for internal review. Make unsupported or conflicting claims visible before approving a deliverable.
How to test it
Generate a draft from known evidence, then request a claim those files do not support.

Check whose account the document connection uses. A connection using the app creator’s account may access documents the person asking cannot read.3

Follow the copies, not just the database

Scenario: A source file is deleted, but its text remains in the search index, an old draft and a debugging log.

Source documents→Search index→Passages sent to the AI→Drafts and approved documents
Also check: conversation history, caches, exports, backups and monitoring logs.

How to prevent it

For each copy, define access, retention and deletion. Keep logs focused on actions and outcomes; decide separately whether document text belongs there.4

How to test it

Delete a test file and check its index entries, drafts, exports and logs against the documented retention policy. Verify how backups are handled and how restored data avoids reappearing without permission.

A document is evidence, not an instruction

Scenario: An uploaded supplier document contains hidden instructions to copy internal pricing into a client deliverable.

A retrieved document might tell the assistant to search a restricted collection or share a deliverable with a client. This is prompt injection: instructions hidden in material the AI should only analyse. Filters help, but the application must check permissions and allowed actions independently of the model.56

Give the AI specific tools for reading this workspace’s files and saving its drafts. Sharing should release only the approved deliverable, not grant membership of the workspace or access to all its files. Limit which systems those tools can contact. Test a document containing hidden instructions and inspect what the assistant actually accessed or shared, as well as its draft.10

Approve exactly what the client will receive

Scenario: A document is approved for a client, then someone edits it to include an internal note before sharing.

Share only the approved document version. Client access to that deliverable must not grant access to the workspace’s files or internal source references.

Protect the browser

Scenario: An AI-written document includes HTML that runs unwanted code when a colleague previews it.

How to prevent it

Render text safely, sanitise permitted rich content and protect sessions. Keep API keys out of browser code; enforce permissions on the server.3842

How to test it

Test malicious preview text, signed-out access and direct requests for actions hidden in the interface.

Enforce access on the server

Scenario: A user changes a file ID in a download request and receives another team’s source document.

How to prevent it

Check organisation, workspace and action permissions on every request and job. Validate inputs, limit request volume and separate read, edit and share permissions.237

How to test it

Swap IDs, remove membership during generation, and test reader, editor and client roles.

Treat uploaded files as untrusted

Scenario: A file labelled as a PDF is malformed and attacks the service that extracts its text.

How to prevent it

Allow required file types, verify content and size, scan uploads and isolate file processing. Keep source files read-only to the AI; limit generation time, usage and tool access.3656

How to test it

Try a disguised file, an oversized upload and hidden instructions. Confirm no cross-workspace content or unauthorised sharing.

Check where processing happens

Scenario: Files are stored in the chosen region, but the selected AI deployment processes their text elsewhere.

How to prevent it

Check where each service stores and processes data, including any cross-region routing. Match the actual deployment settings to the organisation’s requirements.4647 Encrypt stored data, restrict key access and define retention for files, indexes, drafts, logs and backups.41

How to test it

Trace a test file through every service. Verify configured locations, access and the documented deletion/backup lifecycle.

Limit the app’s network reach

Scenario: An agent tool follows a document-supplied URL and attempts to send confidential content to an unapproved server.

How to prevent it

Use encrypted connections, restrict incoming and outgoing traffic, and keep private services off public routes. Use private endpoints or network isolation where the chosen services support them.3940

How to test it

Try access from an unapproved network and calls to blocked destinations. Test DNS and routing as well as permissions.

Protect the route into production

Scenario: A release changes a storage setting to public, or a build job exposes deployment credentials.

How to prevent it

Separate development, test and production. Restrict deployment accounts, manage secrets centrally, review changes and scan code, dependencies and infrastructure configuration.431

How to test it

Use synthetic test data, retain release evidence and rehearse rollback, recovery and disabling AI/sharing tools.

A workspace is an access boundary within the app; it is not necessarily a separate customer tenant. Tenant-isolation guidance is useful for reviewing shared storage, caches and background jobs.44

These are starting checks, not a complete assessment. Private networking does not replace user permissions; content screening does not secure the browser or deployment pipeline.

Match each tool to a specific problem

Scenario: The code scanner passes, but a client can still open an internal file. Choose tools and workflow tests that cover the actual failure.

Use existing organisational tooling first. Code review, dependency checks, web testing and AI attack testing cover different layers.

Illustrative market options, not a ranking or required shopping list. Start with existing controls and compare candidates against the same failure cases.

Code analysis

Find flaws in application code

For instance: CodeQL, Semgrep, Snyk Code and Claude Security.4814161112

Compare language coverage, supported frameworks and reviewable findings. Fixes still need regression tests.

Libraries and build artefacts

Check what the app depends on

For instance: Snyk Open Source and Trivy.1752

Scan the relevant libraries, images and build artefacts. Prioritise exploitable findings; test upgrades.

Web testing

Test the running application

For instance: ZAP and Burp Scanner.1853

Configure signed-in coverage. ZAP baseline is passive; active testing needs a controlled test environment.

AI attack testing

Exercise the full AI workflow

For instance: Promptfoo, PyRIT and Mindgard.19205421

Test document injection, cross-user access and tool misuse. Inspect side effects as well as generated text.

Runtime screening

Inspect live AI inputs and outputs

For instance: Check Point AI Guardrails (Lakera documentation), Prisma AIRS and Model Armor.495123

Compare blocking modes, missed attacks, incorrect blocks, latency and how inspected data is handled.

Permissions

Enforce access to each object

For instance: an application permission layer or an authorisation service such as OpenFGA.8

The server must enforce the decision for files, drafts and sharing. A login or content filter cannot substitute for it.

Cloud and configuration

Find exposed resources and unsafe settings

For instance: Wiz for cloud/application exposure, and Trivy for configuration and artefact checks.2452

Verify the selected modules and deployment coverage. Reproduce the exposure and test the fix.

Agent and low-code governance

Track agents, connections and allowed behaviour

For instance: Zenity and platform policies such as Copilot Studio data policies.5022

Check supported platforms, inventory coverage and which actions are monitored versus blocked.

Platform controls

Use existing services where they fit

For instance: managed retrieval, identity, guardrail and private-network features in your current platform.

Choose by the required control and verify its limits. Cloud-specific examples are below; they are not a proposed stack.

Check deployment and trust before enabling a scanner

Semgrep Community Edition can scan locally. Hosted and managed options may handle source code or findings differently; verify their terms and permissions.15

Claude Security: which product are we talking about?

The February research preview was named Claude Code Security. Current documentation describes Claude Security, an Enterprise public beta and a Claude Code plugin.291112

The separate security-review GitHub Action is intended for trusted pull requests; its repository says it is not hardened against prompt injection. Check workflow permissions before enabling it.13

For instance: controls already available in cloud platforms

Document access: Azure AI Search and Bedrock Knowledge Bases offer permission-aware retrieval patterns. Check permission updates, source support and preview limits. AWS custom-source ACL filtering relies on identity supplied by the application.93134

Content and agent controls: Foundry Prompt Shields, Bedrock Guardrails and Google Model Armor are examples of screening capabilities. AgentCore Identity is one example of agent credential management. Validate the configured path; these services do not establish every user’s right to each file.3032352333

Location and networking: for instance, Azure Global/DataZone deployments and AWS cross-region inference have different processing-location rules. Azure network isolation and AWS PrivateLink illustrate private-connectivity options. Confirm current region, service and integration support.46473940

Test the safeguards and keep the results

Scenario: A fix blocks one leaked-file request, but the same file is still available through an export. Retest every relevant route.

Risk→Safeguard→Responsible person→Test→Result
Different usersUsers cannot search, open sources or export material from workspaces they cannot access.
Revoked accessSearch results, stored drafts and saved deliverables stop working within the agreed time after access is removed.
Injected documentNo unauthorised retrieval, tool call or external share.
Changed approvalChanged content needs new approval. Expired or reused approvals fail; retries do not send twice.
Missing evidenceDrafts flag unsupported claims; internal source references support the text. Client-visible references do not expose restricted files.
Protection outageIf a required permission check is unavailable, stop the request. Define what happens when content screening is unavailable too.

Run code, library and access checks automatically when the code changes. Test signed-in web pages and AI attacks in a test deployment. Keep the tested versions, confirmed issues, fixes and expiry dates for any exceptions.

Which frameworks help choose the checks?

OWASP ASVS: application requirements. OWASP LLM and Agentic Top 10: model and tool risks. MITRE ATLAS: adversary scenarios. NIST SSDF: development practices and evidence. Framework mapping is not certification.7525261

Start small. Review new access and actions.

Scenario: The pilot only saves internal drafts. The next release adds client sharing and a new document source. Recheck the affected boundaries before enabling them.

First release

One team. Separate workspaces. Approved file types. AI-written drafts. Named reviewers and approved sharing.

Review triggers

New file types, model or connection. Sources reused across workspaces. Client access. New editing, publishing or sharing tools.

Ownership and obligations

Name who supports the app and who can stop it. Check privacy requirements, contract restrictions and how long data may be kept; technical tests alone do not resolve these.

Keep a route to disable tools, roll back changes and retire the app. The release decision should explain who may use this version, with which data and actions—and point to the evidence.
